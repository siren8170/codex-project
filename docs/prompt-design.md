# 프롬프트 설계서

## 1. 목표
Flutter를 이용하여 마이크 녹음으로 하루를 기록하고, 설정된 라이프사이클에 따라 오디오를 관리하며 텍스트 일기를 작성·보관하는 모바일 애플리케이션을 구현합니다.

## 2. 맥락
- 사용자는 모바일 기기에서 짧은 음성 녹음으로 일상을 기록합니다.
- 하루 전환 시각(21:00 ~ 09:00)을 설정하여, 자정이 넘은 새벽 기록도 사용자의 생활 패턴에 맞게 전날 일과로 귀속시킵니다.
- 오디오 파일은 사용자가 설정한 보관 기간(1~14일) 동안 유지되며, 필요한 파일은 기기에 직접 다운로드(내보내기)할 수 있습니다.
- 텍스트 일기는 당일 녹음을 바탕으로 생성되며, 기록의 진정성을 위해 일기가 생성된 논리적 당일에만 수정할 수 있고 지난 일기는 읽기 전용이 됩니다.
- 캘린더에서 날짜별 일기를 조회할 수 있습니다.
- Dart 기초를 알고 있는 개발자 관점에서 가독성 있고 테스트 가능한 코드로 작성합니다.

## 3. 제약
- **개발 환경:** Flutter (Dart), Android 및 iOS 네이티브 권한 대응 (`permission_handler`).
- **아키텍처:** 하네스 엔지니어링을 위해 UI와 비즈니스 로직, 시간/오디오/저장소 서비스를 추상 인터페이스로 분리합니다.
- **시간 제어:** 시스템 시계(`DateTime.now()`)에 직접 의존하지 않고, 시간 모킹이 가능한 `TimeService`를 통해 논리적 날짜를 산출합니다.
- **데이터 보관:**
  - 오디오 파일: 앱 로컬 디렉터리에 파일 형태로 보관하며 설정된 TTL(1~14일) 초과 시 자동 삭제.
  - 일기 텍스트: 로컬 DB(SQLite/Hive 등)에 영구 보존.
  - 환경 설정: Key-Value 저장소(`shared_preferences`)에 보관.
- **예시 데이터:** AI STT/요약 엔진 연동 전까지는 결정론적 Mock 데이터를 반환하는 인터페이스를 통해 파이프라인을 검증합니다.
- 외부 서버나 사용자 계정 없이 온디바이스 로컬 환경에서 단독 동작해야 합니다.

## 4. 출력 형식
- 구현할 파일 목록과 파일별 역할을 한 줄씩 명시하세요.
- 비즈니스 로직(시간, 삭제, 수정 정책)에 대한 인터페이스 계약과 테스트 코드를 먼저 제시하세요.
- 화면 구성(위젯 구조) 및 사용자 확인 절차를 명확한 행동/결과로 적어 주세요.

## 5. 완료 기준 (Acceptance Criteria)
1. **마이크 권한 및 녹음:** 마이크 접근 권한을 획득하고 음성을 녹음하여 로컬에 저장할 수 있다.
2. **오디오 보관 주기 제어:** 1일~14일 사이로 설정된 보관 기간을 초과한 과거 오디오는 앱 실행 시 자동으로 영구 삭제된다.
3. **오디오 다운로드/내보내기:** 보관함의 오디오 파일을 사용자가 기기 외부/공유 폴더로 저장할 수 있다.
4. **하루 전환 기준 시각 반영:** 21:00~09:00 사이로 설정한 전환 시각 이전까지 생성된 모든 녹음과 일기는 동일한 논리적 날짜로 묶인다.
5. **일기 생성 및 당일 수정 잠금:** 당일 오디오를 기반으로 일기 초안이 생성되며, 일기가 생성된 논리적 당일에만 수정·저장할 수 있고 과거 일기는 읽기 전용으로만 열람된다.
6. **캘린더 조회:** 캘린더에서 일기가 있는 날짜를 마커로 확인하고, 날짜 선택 시 해당 일의 일기 내용을 볼 수 있다.

## 6. 테스트 하네스 검증 시나리오 (자동화 검증)
- 전환 시각 04:00 설정 시, 10월 2일 03:30의 기록이 10월 1일 논리적 날짜로 판정되는지 단위 테스트 검증.
- 보관 기간 3일 설정 시, 4일 전 파일만 삭제되고 3일 이내 파일은 유지되는지 단위 테스트 검증.
- 어제 작성된 일기에 대해 `DiaryPolicy.canEdit`이 `false`를 반환하고 수정을 거부하는지 단위 테스트 검증.
